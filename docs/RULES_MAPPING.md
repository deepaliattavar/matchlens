# Submission scope and requirements

Reference checked October 26, 2026: https://github.com/microsoft/insidethegamehackathon/blob/main/OFFICIAL%20RULES.md

| Area | Evidence or remaining action |
| --- | --- |
| Synthetic data | Authored event CSV, context storyline and reproducible scenario generator; no real match data |
| Ingest / interpret | Event-prefix replay, validation, possession outcomes, pass accuracy, pressure links |
| Explain | Historical context, pending versus resolved outcomes, evidence IDs |
| Render | Story/comparison cards, static HTML and timed JSON; production synchronization not implemented |
| Personalize | Club/team, fan/analyst, English/Spanish; dedicated player-focused UI not included |
| Narratives / recaps | Prepared wording, deterministic recovery recap and historical milestones; not comprehensive tactical analysis |
| Microsoft technology | Optional Foundry Local / Phi-4-mini drafting; reviewed wording powers default replay |
| Code access | Runnable source and README prepared; entrant must publish GitHub repository |
| Video and language | English 110-second script prepared; entrant must record and publish actual functioning footage |
| Testing access | No-model desktop test build; entrant must make it publicly accessible through judging |
| Rights and eligibility | Fictional team names used throughout; entrant confirms eligibility, original work and any third-party permissions |
| Category fit | Closest technical relationship is Foundry; no guarantee of a specific category's eligibility or award |

Optional suggested features such as video auto-eventing, ball speed and pass difficulty are not implemented. The project's narrow analytical focus and limited AI autonomy are judging limitations, not hidden completed features. Public submission and publication remain undone until the entrant performs them.
